# 橫縱分析法深度研究

> **方法論溯源**
> 橫縱分析法由數字生命卡茲克（Khazix）提出，融合了語言學中的歷時-共時分析（Saussure）、社會科學中的縱向-橫截面研究設計、商學院案例研究法、以及競爭戰略分析的核心思想，形成了一套適用於產品/公司/概念/人物的通用研究框架。核心原則不變：縱向追時間深度，橫向追同期廣度，最終交匯出判斷。

你正在執行一次橫縱分析法深度研究。最終產出一份**排版精美的PDF研究報告**。

## 前置準備

### 環境準備

1. **確認PDF轉換腳本可用**：本Skill自帶 `scripts/md_to_pdf.py`（基於WeasyPrint），用於將最終Markdown報告轉為排版精美的PDF。確保依賴已安裝：`pip install weasyprint markdown --break-system-packages`。
2. **寫作風格**：本Skill已內建完整的寫作風格指南（見下文"寫作風格"部分），無需額外載入其他skill。

### 明確研究對象

拿到使用者輸入後，確認以下資訊。如果使用者已經給得足夠明確（比如"幫我用橫縱分析法研究Hermes Agent"），不需要追問，直接開始：

1. **研究對象**：具體的產品名/公司名/概念名/人名
2. **類型**：產品、公司、概念、人物、還是其他？
3. **研究動機**（可選）：為什麼要研究它？最近發生了什麼？
4. **特別關注點**（可選）：有沒有特別想深入的方向？

## 第一步：聯網資訊收集

這個方法論的質量完全取決於資訊的豐富度和準確性。**必須聯網搜尋**，不能僅靠已有知識。研究報告的價值在於深度和完整度，所以資訊收集階段寧可多搜，不要因為資訊不夠導致後面的分析浮於表面。

### 並行搜尋策略

使用子Agent並行搜尋來提高效率。建議的分工：

- **子Agent 1 — 縱向資訊**：研究對象的起源、創始人背景、發展歷程、關鍵事件、版本迭代、融資、戰略轉向、危機
- **子Agent 2 — 橫向資訊**：競品識別、各競品的特點和使用者口碑、行業對比評測、市場份額
- **子Agent 3**（複雜對象才需要）：補充資訊，如創始人深度背景、行業環境變化、使用者社群討論（GitHub issues、Reddit、Twitter/X、知乎等）

**子Agent聯網工具使用指南**（直接寫入每個子Agent的prompt中）：

每個子Agent的prompt中必須包含以下聯網指引：

> 你需要聯網獲取資訊。使用以下工具：
> - **WebSearch**：用於搜尋發現資訊來源，獲取摘要和關鍵詞結果
> - **WebFetch**：當已知具體URL時，用於從頁面定向提取內容
> - 如果使用者環境中安裝了 web-access skill（檢查路徑 `/mnt/.claude/skills/web-access/SKILL.md` 是否存在），優先載入它並遵循其指引，它提供更強的瀏覽器CDP能力
> - 搜尋策略：先用WebSearch發現資訊來源和線索，找到具體URL後用WebFetch深入提取
> - 多次搜尋、多個關鍵片語合，不要只搜一次就放棄
> - 一手來源優於二手來源：官方部落格 > 權威媒體原創報道 > 轉載/聚合
> - **學術類研究對象必查arxiv**：如果研究對象涉及學術概念、演算法、AI模型、技術範式等，必須透過arxiv API獲取相關論文。呼叫方式：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词1+AND+all:关键词2&max_results=10"`，或用WebFetch訪問同一URL。返回XML格式，包含標題、作者、摘要、釋出日期、PDF連結。可按需調整關鍵片語合和結果數量。找到關鍵論文後，用WebFetch讀取論文頁面（`https://arxiv.org/abs/论文ID`）獲取更多細節。

prompt要描述目標（"獲取""調研""瞭解"），不要用暗示具體手段的動詞（"搜尋""爬取"），讓子Agent自主判斷最佳獲取方式。

### 資訊來源優先順序

一手來源優於二手來源，多個媒體引用同一個錯誤會造成迴圈印證假象：

| 資訊類型 | 一手來源 |
|---------|---------|
| 產品更新/技術決策 | 官方部落格、GitHub Release Notes、創始人推文 |
| 融資/商業資料 | 公司官方公告、SEC/工商檔案 |
| 使用者口碑 | GitHub Issues、Reddit討論、Twitter/X、知乎帖子 |
| 行業分析 | 權威媒體原創報道（非轉載） |
| 學術/技術原理 | arXiv論文（`export.arxiv.org/api/query`）、Google Scholar、學術會議論文集 |

### 資訊充分性自檢

搜尋完成後檢查：
- 縱向：能講出一個完整的故事嗎？有沒有明顯的資訊斷層？
- 橫向：競品列表完整嗎？有沒有遺漏主要玩家？每個競品的資訊夠做對比嗎？
- 來源：關鍵事實有可靠來源支撐嗎？有沒有隻靠單一來源就下判斷的？

資訊不夠就再補搜。不要湊合。

## 第二步：縱向分析（Diachronic / Longitudinal）

沿時間軸，完整還原研究對象從誕生到現在的發展全貌。這是報告的主體部分，篇幅應該最重。

### 內容要求

**起源追溯**：它誕生的背景是什麼？基於什麼技術/理念/需求而來？創始團隊或核心推動者是誰？這些人之前做過什麼，為什麼是他們來做這件事？當時的行業環境是什麼樣的？有沒有某個關鍵事件或靈感直接促成了它的誕生？

**誕生節點**：明確的首次釋出/成立/提出時間，最初的形態和定位，跟現在有什麼不同。

**演進歷程**：從誕生到現在，按時間順序梳理所有關鍵節點。包括但不限於：重大版本更新、融資事件、團隊變動、戰略轉型、技術架構變化、使用者規模里程碑、重大合作或收購、公關危機或爭議事件。

**決策邏輯**：在每個關鍵節點上，儘可能還原決策背後的原因。為什麼選了A而不是B？當時面對的約束條件是什麼？哪些早期決策"鎖定"了後來的發展方向、難以逆轉？什麼機制讓它越走越深（網路效應、生態繫結、技術棧選擇等）？

**階段劃分**：把整個歷程自然分為幾個階段（萌芽期、快速增長期、轉型期等），每個階段有核心特徵和核心矛盾。

### 篇幅

6000-15000字。歷史越長、節點越多的對象靠近上限，新生事物靠近下限。核心原則是把故事講完整、講透，每個關鍵節點都值得展開，不要為了壓縮而跳過重要細節。寧可寫長寫細，也不要蜻蜓點水。

## 第三步：橫向分析（Synchronic / Cross-sectional）

以當前時間點為切面，將研究對象與同賽道的競品/同類進行全面對比。

### 首先判斷競品情況

分三種場景處理：

**場景A：無直接競品。** 如果研究對象是全新品類或獨佔性極強的領域，跳過逐一對比，改為分析：它為什麼沒有競品？是品類太新、壁壘太高、還是市場太小？未來最可能從哪個方向冒出競爭者？有沒有間接替代方案或上一代解決方式可以參照？

**場景B：少量競品（1-2個）。** 逐一深入對比，每個競品展開詳細分析。

**場景C：競品充分（3個及以上）。** 選取最具代表性的3-5個進行對比，其餘簡要提及。

### 對比維度

根據研究對象的類型靈活調整，但至少覆蓋以下方面：

**核心差異對比**：技術路線/核心方法論/底層邏輯、產品形態/商業模式/組織結構、目標使用者/受眾/適用場景、核心優勢與明顯短板、定價策略/資源投入/規模體量。

**使用者視角**：每個競品的真實使用者口碑如何？社群評價、使用體驗中被提及最多的優點和槽點分別是什麼？使用者實際的使用方式和官方定位有沒有偏差？對比不要寫成參數對照表的文字版，要講清楚每個競品「活成了什麼樣」，使用者選它的真實理由是什麼。

**生態位分析**：在整個賽道的版圖中，研究對象佔據什麼位置？填補了什麼空白，還是在跟誰正面競爭？當前格局是百花齊放、兩強爭霸、還是一家獨大？

**趨勢判斷**：基於橫向對比，研究對象在競爭格局中的走向是什麼？機會和風險各是什麼？

### 篇幅

3000-10000字。場景A控制在3000字左右，場景C每個主要競品至少展開1500字以上的獨立分析，不要一筆帶過。

## 第四步：橫縱交匯洞察

這是整篇報告的精華段。把縱向發展脈絡和橫向競爭格局結合起來，給出綜合性的、新的判斷。不要寫成前面內容的縮寫版。

需要回答的核心問題：

1. **歷史如何塑造了當下的競爭位置**：縱向歷程中的哪些決策和事件，決定了它今天在橫向對比中的位置？
2. **競品的縱向對比**：如果把主要競品也放到時間線上看，它們的起源和演變路徑有什麼不同？這些不同如何導致了今天各自的特點？
3. **優勢的歷史根源**：今天的每個核心優勢，能追溯到歷史上的哪個節點或決策？
4. **劣勢的歷史根源**：今天的每個核心劣勢，能追溯到哪個歷史決策？當初的「好決策」有沒有變成今天的包袱？
5. **未來推演**：基於縱向趨勢和橫向競爭格局，給出三個劇本——最可能的、最危險的、最樂觀的，每個劇本要有邏輯支撐。

### 篇幅

1500-3000字。

## 寫作風格

這不是一份冷冰冰的諮詢報告，而是一篇讓人能從頭讀到尾的深度研究。寫作風格需要在「研究報告的嚴謹」和「卡茲克的可讀性」之間找到平衡點。

### 從卡茲克文風中借鑑的核心元素

以下風格元素直接應用到報告寫作中（詳細定義請參考 khazix-writer skill）：

**節奏感**：句子時長時短，段落之間跳躍自然。不要每段都一樣長，一句話自成一段製造重量感的技巧可以用。好的節奏像波動，每次圍繞主線偏出去一點，再用一句「扣主線句」拉回來。

**敘事驅動，不是羅列驅動**：縱向部分要有故事弧線，有起承轉合。比如一個產品為什麼在某個時間點突然爆發，背後的鋪墊是什麼，轉折是什麼。不要寫成"2023年1月釋出了A，2023年3月釋出了B"這種流水賬。

**知識是「聊著聊著順手掏出來」的**：在講述過程中自然地帶出背景知識，不要「下面我來給大家科普一下」。

**敢下判斷**：鼓勵給出觀點和洞察，但每個觀點必須有事實支撐。先擺事實，再給判斷。是推測的明確標註。表達判斷時用「我覺得」「我的判斷是」這種承認主觀性的姿態，而不是居高臨下的定論。

**層層剝開的修辭**：不直接講結論，用"現象→表面解釋→更深的追問→核心洞察"的方式展開。讓讀者參與到思考過程中。

**文化升維**：在交匯洞察部分，連線到更大的文化/哲學/歷史參照物。不是硬湊的昇華，是「聊著聊著自然想到了」的感覺。

**迴環呼應**：開頭或縱向部分埋的細節和鉤子，在交匯洞察或結尾callback回來。前後因果的閉合感，是讓報告從「資訊流」變成「作品」的關鍵。

### 不從卡茲克文風中借鑑的元素

以下元素適合公眾號文章但不適合研究報告，需要剋制：

- **過強的口語化**：報告可以有聊天感，但不要滿篇「這玩意」「不是哥們」「太牛逼了」。偶爾點綴可以，但密度要比公眾號文章低很多。
- **去小標題化**：公眾號文章追求一口氣順下來不加小標題。研究報告不一樣，1-3萬字的內容如果沒有清晰的結構和導航，讀者會迷路。報告需要清晰的章節結構。
- **標點禁令可以放鬆**：公眾號文章禁用冒號和破折號。研究報告中可以正常使用，因為報告需要的是資訊傳達效率。但「」的使用習慣可以保留。
- **固定尾部**：不要加公眾號的三連/星標尾部。

### 絕對禁區（依然適用）

以下AI味標記無論什麼文體都要避免：
- 套話："首先...其次...最後"、"綜上所述"、"值得注意的是"、"不難發現"
- 空洞形容詞："賦能"、"抓手"、"打造閉環"
- 教科書開頭："在當今AI快速發展的時代"、"隨著技術的不斷進步"
- 高頻踩雷詞："說白了"、"意味著什麼？"、"這意味著"、"本質上"、"換句話說"、"不可否認"
- 空泛工具名：不說"AI工具"、"某個模型"，要說具體名字
- 編造場景：如果某個資訊搜不到，誠實標註「該資訊暫缺」，絕不編造

### 用人話寫

避免諮詢公司式的套話和空洞概括。用具體的細節和例子代替概括性陳述。比如不要寫「該公司在這一階段實現了快速增長」，而要寫「從2024年中期的1000萬美元ARR到2025年底的10億美元，增長曲線幾乎是垂直的」。

## 第五步：生成PDF報告

報告寫完後，使用本Skill自帶的 `scripts/md_to_pdf.py` 腳本將Markdown轉為排版精美的PDF。

### 轉換流程

1. **先完成Markdown稿件**：將完整報告寫為標準Markdown格式，儲存為 `[研究对象]_横纵分析报告.md`
2. **安裝依賴**（如未安裝）：`pip install weasyprint markdown --break-system-packages`
3. **執行轉換腳本**：
   ```bash
   python [skill目录]/scripts/md_to_pdf.py input.md output.pdf --title "研究对象名称" --author "数字生命卡兹克"
   ```
4. 腳本會自動生成中間HTML檔案（便於除錯）和最終PDF

### 腳本內建的排版規範

`md_to_pdf.py` 已內建完整的CSS排版方案，無需手動調整：

- **頁面**：A4，頁邊距上25mm/左右20mm/下20mm
- **封面頁**：自動生成，包含標題（28pt深藍色）、副標題「橫縱分析法深度研究報告」、作者資訊、裝飾分隔線
- **配色**：H1標題=#1a5276深藍、H2=#1e8449綠色、H3=#2e86c1淺藍、H4=#5b2c6f紫色，正文=#2c3e50深灰
- **字型**：CSS fallback鏈 `"Droid Sans Fallback", Helvetica, Arial, sans-serif`，自動處理中英文混排
- **正文**：10.5pt，行距1.75，兩端對齊，孤行/寡行控制
- **引用塊**：左側3pt深藍豎線 + 淺灰背景
- **表格**：全寬、深藍表頭白字、斑馬紋行
- **頁首**：「報告標題 | 橫縱分析法深度研究報告」（首頁不顯示）
- **頁尾**：「第 X 頁」（首頁不顯示）
- Markdown的第一個H1會被自動提取為封面標題，正文中不會重複出現

### Markdown寫作注意事項

為了讓腳本正確解析並生成最佳PDF效果：

- 第一行用 `# 标题` 作為報告標題（會自動用於封面）
- 緊接標題後可用 `> 研究时间：... | 所属领域：... | 研究对象类型：...` 格式寫元資訊行，會被提取到封面
- 用 `##` 作為主要章節標題（縱向分析、橫向分析、橫縱交匯等）
- 用 `###` 和 `####` 作為子章節
- 表格使用標準Markdown表格語法
- 引用使用 `>` 語法
- 加粗使用 `**文本**`

### 末尾內容

在Markdown稿件末尾加上：
- **資訊來源**：所有引用的來源清單，標註URL和訪問時間
- **方法論說明**：簡要說明橫縱分析法的來源（1-2句話即可）

## 不同研究對象類型的適配

核心原則不變（縱向追時間深度，橫向追同期廣度），但側重點不同：

**研究產品時**：縱軸重點關注版本迭代、技術路線演變、使用者增長曲線、關鍵產品決策；橫軸重點關注功能對比、效能對比、使用者體驗、定價。

**研究公司時**：縱軸重點關注創始團隊、融資歷程、戰略轉向、組織變革、關鍵人事變動；橫軸重點關注商業模式差異、市場份額、營收對比、組織架構差異。

**研究概念時**（技術範式、商業模式、文化現象）：縱軸重點關注概念的起源（誰提出的、基於什麼理論/需求）、如何流行起來、經歷了哪些爭論和演變；橫軸重點關注與相近概念的區別、各自適用場景、不同陣營的論證。

**研究人物時**：縱軸重點關注個人經歷、職業軌跡、關鍵決策、成長曲線、公開言論變化；橫軸重點關注與同領域其他人物的對比（做事方式、風格、成就、影響力、路線選擇差異）。

## 篇幅總覽

| 部分 | 字數範圍 | 說明 |
|-----|---------|------|
| 縱向分析 | 6,000 - 15,000字 | 報告主體，不要蜻蜓點水 |
| 橫向分析 | 3,000 - 10,000字 | 視競品數量調整 |
| 橫縱交匯 | 1,500 - 3,000字 | 精華段，給出新判斷 |
| **全文總計** | **10,000 - 30,000字** | 不要怕長，深度和完整度是價值所在 |

## 質檢清單

交付前自檢：

- [ ] 縱軸是敘事故事體？讀起來有因果邏輯和時代脈絡？不是年表流水賬？
- [ ] 創始人/發起者的背景和動機有足夠深度？
- [ ] 每個關鍵節點都展開寫了，沒有為了壓縮而跳過重要細節？
- [ ] 決策邏輯有還原？不只是「發生了什麼」，還有「為什麼這麼選」？
- [ ] 橫軸的競品場景判斷正確（A/B/C）？競品分析夠深？
- [ ] 使用者口碑部分引用了真實使用者的聲音？不只是官方宣傳？
- [ ] 橫縱交匯產出了新的判斷，不是前面內容的縮寫版？
- [ ] 未來推演的三個劇本都有邏輯支撐？
- [ ] 寫作風格有節奏感、有可讀性？不是冷冰冰的諮詢報告？
- [ ] 沒有觸犯絕對禁區裡的任何一條？
- [ ] 所有關鍵事實標註了資訊來源？
- [ ] 搜不到的資訊誠實標註了「暫缺」，沒有編造？
- [ ] PDF排版美觀、結構清晰、可讀性好？
- [ ] 總字數在 10,000-30,000 字的範圍內？
